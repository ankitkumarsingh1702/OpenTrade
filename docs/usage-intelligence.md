# OpenTrade usage intelligence

OpenTrade preserves limited aggregate and public-reuse evidence without adding frontend telemetry.

## Private storage

Snapshots, marker configuration, candidate matches, and enforcement review records are stored in the private repository `ankitkumarsingh1702/OpenTrade-usage-intelligence`. No traffic snapshot or suspected-copy report is committed to this public frontend repository.

The private workflow runs daily and collects, where GitHub makes it available:

- aggregate clones and unique cloners;
- aggregate views and unique visitors;
- popular public referrers and repository paths;
- public forks, stars, and watchers;
- required-notice presence in new forks; and
- public GitHub code-search matches for multiple documented provenance signals.

It stores previous state, detects changes, applies weighted confidence scoring, and creates private human-review alerts only for meaningful events. Stars and ordinary views are archived without routine alerts.

## Honest limits

GitHub traffic metrics cover a rolling window and provide aggregate counts, not universal identities. The system cannot reliably identify every person who clones the repository, downloads a ZIP, copies a file, removes Git history, moves code into a private repository, hosts it outside GitHub, or substantially rewrites it.

Forking is not infringement. A missing notice or marker is not conclusive evidence. Similarity scores are triage signals, common framework boilerplate is discounted, and every candidate requires human review.

The official frontend contains no phone-home code, installation identifier, fingerprinting, hidden analytics, or monitoring credential. It sends no usage event to the private intelligence system.

## Enforcement boundary

Monitoring never files takedowns, legal threats, trademark complaints, or public accusations. The private runbook requires evidence preservation, ownership and licence verification, false-positive review, and proportionate human-approved contact before any escalation.
